# 狗了个狗 · 设计文档

> 日期：2026-09-23
> 需求原话：「做一款跟羊了个羊一样的游戏，叫狗了个狗，尽可能把你所有的能力全部都用上，然后上传到CDN给我」
> 已确认：发布 = Claude Artifact + GitHub Pages（Kline-x/gou-le-ge-gou）；第 2 关 = 有解但很难；设计确认后直接开工，不再单独审阅 spec。

## 1. 目标与范围

- 玩法与《羊了个羊》一致的三消堆叠游戏，题材换成狗：图案、吉祥物、文案、音效全部狗狗主题。
- 交付物是**零外链的单文件**，同一套源码构建出两份产物：
  - `dist/index.html`：完整的 HTML 文档，部署到 GitHub Pages，也可以丢到任意 CDN。
  - `dist/artifact.html`：Artifact 页面片段，不带 doctype/html/head/body，由平台套上外壳后发布。

  两份都不依赖任何外部 CDN 或字体，国内也能直接打开。
- 手机竖屏优先，桌面端居中显示成手机比例。
- 成功标准：
  - 今日挑战两关可以完整打通。
  - 第 2 关有解，但普通玩家需要道具加一点运气才能过。
  - 控制台零报错。
  - 手机和桌面尺寸、浅色和深色模式下都能正常显示。
  - 两个发布链接都能打开游玩。

## 2. 玩法规则（精确定义）

### 2.1 牌与覆盖

- 每张牌有 `id`、`kind`（图案编号）、`x`、`y`（单位是牌宽，精度 0.5）和 `z`（层号，越大越靠上）。
- 牌所在的区域（`zone`）有四种：`board`（场上，包括两侧盲盒堆）、`slot`（卡槽）、`buffer`（移出区）、`gone`（已消除）。
- **覆盖判定**：场上的牌 A 被覆盖，当且仅当存在另一张场上的牌 B 满足以下全部条件：
  - `B.z > A.z`
  - `|B.x − A.x| < 1`
  - `|B.y − A.y| < 1`

  被覆盖的牌显示变暗，不能点击。
- **盲盒堆**：底部左右各一堆。它们同样用几何方式表达：同一堆里每张牌的 x 依次偏移 0.1、z 依次加 1，因此只有最上面一张是空闲的，下面的牌只露出一条边。
- **移出区**：共 3 列，每列是一个栈，只有栈顶可以点。移出区的牌不参与场上的覆盖判定。

### 2.2 卡槽

- 卡槽容量为 7。
- 牌进入卡槽时：如果槽里已经有同图案的牌，就插在最后一张同图案牌的后面；否则放到末尾。
- 插入后，如果该图案在槽里凑满 3 张，这 3 张立即消除（进入 `gone`）。
- **连消（combo）**：如果距离上一次消除不超过 3 次拿牌，combo 加 1，否则重置为 1。界面据此依次显示「汪！」「汪汪！」「汪汪汪！」「狗王驾到！」。

### 2.3 胜负

- 失败：消除判定之后，卡槽里仍有 7 张牌，状态变为 `lost`。
- 胜利：`board`、`buffer`、`slot` 里都没有牌了，状态变为 `won`。

### 2.4 道具与复活（每关各 1 次）

| 道具 | 规则 | 不可用时 |
|---|---|---|
| 移出 | 把卡槽最左边的 3 张（不足 3 张就全部）依次放到移出区第 0、1、2 列的栈顶 | 卡槽为空 |
| 撤回 | 把最后一次放进卡槽、且还没被消除的牌放回原来的位置（原来在场上就回到原坐标，原来在移出区就回到原来那一列） | 卡槽为空，或者上一步发生了消除 |
| 洗牌 | 场上所有牌（含盲盒堆）的位置不变，只重新分配图案；尽量保证重新分配后仍然有解（见 3.4） | 场上没有牌 |
| 复活 | 只能在失败时使用，效果等于一次「移出」，不占用移出道具的次数，然后继续游戏 | 已经用过 |

道具用完后再点，按钮会抖一下，并提示「这个道具用完啦」。不做「看广告 / 分享换道具」。

### 2.5 模式与关卡

- **今日挑战**：先打第 1 关（教学，极简单），过了才解锁第 2 关（地狱）。种子是 `dog-YYYY-MM-DD`（取玩家本地日期），所以同一天所有人玩的是同一关。第 2 关通关后，给本地记录的阵营「加一只狗」，并记为今日已通关。
- **自由练习**：简单、普通、困难、原味地狱四档，每局随机种子。「原味地狱」不保证有解。
- 第 1 关在进入时显示新手引导：一个手指动画指向一张可点的牌，同时解释规则。

## 3. 关卡生成与有解保证

### 3.1 几何布局

- 场地大小为 `cols × rows` 个牌位（默认 7 × 8）。
- 每层随机选一个偏移 `(ox, oy) ∈ {0, 0.5}²`，相邻两层尽量错开，这样能形成半张错位的压叠。
- 每层在网格上生成一个随机的**左右对称**掩码，密度为 `density`。越往上的层，可用区域向中心收缩 `shrink`，整体形成堆叠感。
- 同一层内的牌按整格排布，互不重叠。
- 牌总数用各图案的配额决定：场上加盲盒堆的总数必须等于 `Σ 每种图案的张数`（每种都是 3 的倍数）。多出来的牌从最顶层对称地删掉，不够就在最顶层补。
- 两侧盲盒堆各有 `stackSize` 张，位于 `y = rows + 0.3`。

### 3.2 拿牌路径模拟与图案分配（有解保证）

1. 计算覆盖关系 `coveredBy[i]`，即压在 i 上面的所有牌。
2. 模拟拿牌过程：每一步从当前空闲的牌里随机拿一张（上层的牌权重略高），得到拓扑序 `P`。
3. 沿着 `P` 依次分配图案，同时维护一个虚拟卡槽 `open`，记录每个图案当前在槽里有几张（1 或 2）：
   - 候选图案需要同时满足三个条件：
     - 剩余配额大于 0。
     - 放进去之后，虚拟卡槽的占用（消除之后计算）不超过 6。
     - 如果是新开的图案，当前打开的图案数要小于 `kOpen`，并且该图案的剩余配额至少为 3。
   - 如果占用已经 ≥ 5 且存在对子，优先补齐对子；否则按 `pContinue` 的概率延续已打开的图案，其余情况开新图案。
4. 由此得到的 `P` 就是一条**不用道具也能通关**的解，按这条路走，卡槽里最多只有 6 张。生成器会把 `P` 作为 `solution` 一起返回，供测试和调试接口使用。
5. 配额守恒保证这个过程总能完成（所有未打开图案的剩余配额都是 3 的倍数，所以总有合法选择）。「原味地狱」跳过这一步，直接随机分配。

### 3.3 难度参数（初值，实现时用 3.5 的平衡模拟校准）

| 关卡键 | 图案种数 | 每种张数 | 层数 | 盲盒堆 | kOpen | 备注 |
|---|---|---|---|---|---|---|
| `daily1` | 3 | 6 | 2 | 0 | 1 | 教学，18 张 |
| `daily2` | 15 | 12 | 12 左右 | 2 × 12 | 3 | 约 180 张，地狱 |
| `easy` | 6 | 6 | 4 | 0 | 2 | |
| `normal` | 10 | 9 | 7 | 2 × 6 | 2 | |
| `hard` | 14 | 12 | 10 | 2 × 10 | 3 | |
| `hell` | 16 | 12 | 12 | 2 × 12 | — | 纯随机，可能无解 |

### 3.4 洗牌的有解重分配

- 洗牌时，把场上的牌（含盲盒堆）作为待分配集合，图案配额就是这些牌现有图案的多重集合。
- 移出区的牌图案固定不变，但会参与路径模拟：栈顶是空闲的，只有当它的图案放进虚拟卡槽后仍然合法时，才会被选进路径。
- 虚拟卡槽的初始状态等于当前真实的卡槽。
- 按 3.2 的方法进行模拟，`kOpen` 取 3，并允许初始打开的图案数超过 3。最多重试 30 次；全部失败就退化为纯随机洗牌。纯随机的情况通常是局面已经无法挽救，比如槽里是 6 张各不相同的单张。
- 洗牌后，每张牌的位置保持不变，图案的多重集合也保持不变。

### 3.5 平衡模拟

- `tools/balance.mjs` 用两种机器人玩家各跑 N 局，输出每一档难度的通关率：
  - 贪心机器人：优先补齐三张，其次凑对子，再次拿场上同图案空闲牌最多的那种；如果还一样，选压住别人最多的那张。
  - 贪心机器人加道具：卡槽 ≥ 5 张时用移出，卡住时用洗牌，失败时复活。
- 校准目标：

  | 关卡 | 贪心机器人加道具的通关率 |
  |---|---|
  | `daily1` | 100% |
  | `easy` | 90% 以上 |
  | `normal` | 50% 到 80% |
  | `hard` | 20% 到 50% |
  | `daily2` | 5% 到 25% |

  人会比贪心机器人聪明一些，因为能看全局，还能用撤回。

### 4.2 狗狗形象

- 用参数化的狗头 SVG 生成器 `dogHeadSVG(breed, mood)` 画出 6 个阵营的头像：柴犬、哈士奇、柯基、金毛、泰迪、田园犬。
- 吉祥物就是柴犬，有 6 种心情：
  - `idle`：会眨眼
  - `happy`：眯眼笑
  - `worried`：冒汗
  - `sad`：流泪
  - `cheer`：星星眼
  - `shock`：瞪眼
- 心情由局势驱动：
  - 消除时切到 `happy`
  - 卡槽 ≥ 5 张时切到 `worried`
  - 失败时切到 `sad`
  - 通关时切到 `cheer`
  - 点到被压住的牌时切到 `shock`（持续 0.6 秒）

### 4.3 背景与昼夜

- 浅色模式是白天草坪：翠绿底色，加割草机留下的横条纹，再叠一层淡淡的爪印图案（用内联 SVG 的 data URI）。
- 深色模式跟随系统 `prefers-color-scheme`，也可以用 `data-theme` 强制指定，画面是夜晚后院：墨绿草地、月亮和星星。牌面稍微压暗，但保持对比度。

### 4.4 Logo 与 UI 风格

- Logo「狗了个狗」用系统字体最粗的字重，4 个字分别是橙、绿、蓝、粉 4 种颜色。文字有白色粗描边（`paint-order: stroke`）和深色投影，并且带一点倾斜和错落。
- 按钮是卡通风：粗深色描边，底部有实色投影，按下时下沉。圆角要大，要有果冻感。
- 不加载任何网络字体，统一使用系统中文字体栈。

## 5. 音频与触感

- 全部用 WebAudio 实时合成，不读取任何音频文件。
  - 用户第一次点击时解锁 AudioContext。
  - 页面切到后台时自动静音，回到前台再恢复。
- 背景音乐：原创的欢快五声音阶旋律，约 128 BPM，16 小节循环。
  - 乐器：拨弦主旋律、方波贝斯、噪声打击乐。
  - 卡槽 ≥ 5 张时叠加一层「紧张」声部，由 `setTension` 控制。
- 音效共 13 种：

  | 名称 | 场景 | 声音 |
  |---|---|---|
  | `tap` | 点牌 | |
  | `place` | 入槽 | 木头轻敲声 |
  | `match` | 三消 | combo 越高，音高越高 |
  | `woof` | 狗叫 | 共振峰合成的狗叫，有 3 种变体 |
  | `moveOut` | 移出 | 上扬的嗖声 |
  | `undo` | 撤回 | 倒带声 |
  | `shuffle` | 洗牌 | 洗牌沙沙声 |
  | `warn` | 卡槽将满 | 心跳声 |
  | `deny` | 点到被压住的牌 | 闷响（120Hz 加泛音，保证手机外放听得见） |
  | `win` | 通关 | 号角加欢快狗叫 |
  | `lose` | 失败 | 悲伤长号加呜咽 |
  | `revive` | 复活 | 魔法闪光 |
  | `button` | 界面按钮 | |

- 设置中可以分别开关音乐、音效、震动，设置保存在本地。
- 震动（`navigator.vibrate`）：点牌时 8ms；消除时 `[15, 30, 15]`；失败时 `[80, 50, 120]`。

## 6. 界面与交互流程

### 6.1 页面与弹层

- **首页**：
  - Logo 和会动的柴犬。
  - 「今日挑战」按钮，按钮上标出今天的进度：第 1 关、第 2 关或今日已通关 ✓。
  - 「自由练习」按钮，点开后选择难度。
  - 「我的狗群」：切换阵营，查看本地战绩。
  - 「设置」和「玩法」。
  - 在 claude.ai 里打开时，还会显示在线狗友数。
- **游戏页**，从上到下依次是：
  - 顶栏：返回/暂停按钮、关卡名、剩余张数。
  - 场地。
  - 左右两个盲盒堆，中间是移出区。
  - 7 格木质卡槽。
  - 道具栏：3 个按钮，各带剩余次数角标。
  - 吉祥物和气泡台词。
- **弹层**：
  - 暂停：继续、重开本关、回首页。
  - 通关：用时、步数、道具使用情况，战绩图，「AI 狗评」按钮，下一关或回首页。
  - 失败：复活（仅一次）、重来、回首页。
  - 第 1 关过渡到第 2 关时有一段戏剧化的开场：「热身结束，真正的考验来了」。
  - 另有阵营选择、设置、玩法三个弹层。
- 首次打开时先弹出阵营选择；选择之后可以随时去「我的狗群」里更改。

### 6.2 动画与手感

- 点牌后，牌从场上飞入卡槽的目标格，时长 160ms，路线略带弧线，同时缩放。卡槽里的其他牌按 FLIP 方式平移让位。
- 消除时，3 张牌放大后消失，时长 180ms，同时在 Canvas 层炸出骨头、爪印和星星粒子，并飘出 combo 文字。
- 动画播放期间，点击会进入队列（最多排 2 次），不会丢输入，也不会出现画面和逻辑对不上的情况。
- 卡槽 ≥ 5 张时，卡槽边框变红，并且每 1.2 秒抖动一次。
- 开局时牌按层从上方落下，逐层入场，总时长不超过 0.8 秒。
- 通关时撒骨头彩带；失败时卡槽猛烈抖动。
- 系统设置了 `prefers-reduced-motion` 时，只保留必要的位移，去掉粒子和抖动。

### 6.3 适配

- 牌的尺寸根据可用宽高计算：`tile = min((W − 2×16) / cols, 可用高度 / 所需行数)`，并限制在 36 到 64px 之间。窗口大小变化时重新排版。
- 桌面端，游戏区是最大宽度 480px 的竖屏框，居中显示，两侧用背景图案填充。
- 做好安全区适配（`env(safe-area-inset-*)`）。禁止双击缩放和文字选中，页面不出现横向滚动。

## 7. 数据与持久化

- localStorage 的键是 `glgg:v1`，所有读写都包在 try/catch 里；读不到存档时照常以默认值运行。
- 数据结构：

  ```js
  {
    settings: { music: true, sfx: true, vibrate: true },
    team: 'shiba' | null,
    daily: { 'YYYY-MM-DD': { l1: bool, l2: bool, attempts: n, bestRemaining: n } },
    stats: { plays, wins, dailyWins, streak, lastDailyWin, dogsContributed }
  }
  ```

- 不做进行中的对局存档：刷新页面等于重开本关。

## 8. claude.ai 平台能力（渐进增强）

- 只通过 `await window.claude?.use?.(name)` 获取能力。
  - 返回 `null` 或者不存在时，隐藏对应功能。
  - 页面首屏不依赖任何平台能力。
- 声明：

  ```js
  { room: { topics: { win: 'interact' } }, sample: {}, downloads: true }
  ```

  不声明 `db`、`assets`、`mcp`，也不用完整版 `comments`，这样页面可以公开分享。
- **room**：
  - 用 presence 发布 `{ team, screen, level }`，首页显示「在线狗友 N 位」，并列出各阵营人数。
  - 通关今日第 2 关时，在 `win` 话题上发送 `{ team, remaining: 0 }`。其他人会收到 toast「一只柴犬队狗友刚刚通关了今日第二关！」。
  - 收到的数据一律视为不可信：只取白名单里的 team key，文本用 `textContent` 渲染。
- **sample**：
  - 在通关或失败弹层上显示「AI 狗评」按钮，只有玩家点击时才发起请求。
  - 把本局数据（关卡、结果、用时、步数、道具、剩余张数、阵营）连同指令一起发送：「用柴犬口吻、中文、两三句话、毒舌但友善地点评」。
  - 用 `onText` 流式显示在吉祥物气泡里。
  - 遇到 `not_granted` 就隐藏按钮；遇到 `rate_limited` 就提示稍后再试；不做循环重试。
- **downloads**：用来保存战绩图 PNG。Artifact 的沙箱会拦截 `<a download>` 和 Web Share，所以在 claude.ai 里只走 `downloads.save`。
  - 在普通网页里，先尝试 `navigator.share`（带图片文件），失败就退回到 `<a download>` 下载。
  - 两种环境下，都在弹层里直接展示战绩图，手机用户可以长按保存。
- **热更新续玩**：如果存在 `window.claude.hot`，就注册快照 `{screen, levelKey, seedStr, actions}`。页面重新发布之后，用同一种子加上动作日志回放恢复对局，所以洗牌的随机数也要由「种子 + 洗牌次数」决定。
- 页面上不展示任何编造的全网统计数据。

## 9. 工程结构

### 9.1 目录

```
gou-le-ge-gou/
├─ package.json            # "type": "module"，无依赖；scripts: test / build / balance
├─ build.mjs               # 把 src 打包成 dist/index.html（单文件）
├─ src/
│  ├─ index.html           # 页面骨架模板，内含 /*@CSS*/ 和 /*@JS*/ 占位
│  ├─ styles.css
│  ├─ core/  rng.js layout.js generator.js game.js bot.js   # 纯逻辑，不碰 DOM
│  ├─ art/   icons.js dogs.js                                # SVG 字符串生成
│  ├─ audio/ audio.js                                        # WebAudio
│  └─ ui/    storage.js platform.js fx.js share.js board.js screens.js main.js
├─ tests/  *.test.mjs      # node:test

```

### 9.2 模块接口（并行开发的契约）

- **`core/rng.js`**：
  - `hashSeed(str) → uint32`
  - `createRng(seed) → { next(), int(n), pick(arr), shuffle(arr), fork(label) }`，内部用 mulberry32。
- **`core/layout.js`**：
  - `buildLayout(cfg, rng) → [{x, y, z, group}]`，其中 `group ∈ 'main' | 'stackL' | 'stackR'`。
  - `computeCovers(tiles) → { coveredBy: number[][], covers: number[][] }`
- **`core/generator.js`**：
  - `LEVELS`：各档难度的参数表。
  - `generateLevel(key, seedStr) → { key, seed, tiles: [{id, kind, x, y, z, group}], kinds: number[], solution: number[] | null }`
  - `assignKinds(opts) → Map<id, kind> | null`，洗牌时复用。
- **`core/game.js`**：`createGame(level)` 返回一个对象，包含：
  - 查询：`state`（只读）、`isFree(id)`、`freeIds()`
  - 操作：`pick(id)`、`moveOut()`、`undo()`、`shuffle(rng)`、`revive()`，每个操作都返回事件数组；操作非法时返回 `null`。
  - 可用性判断：`canMoveOut()`、`canUndo()`、`canShuffle()`、`canRevive()`
- **事件**（渲染层只根据事件做动画，状态以 `state` 为准）：

  ```
  {type:'pick', id, slotIndex}
  {type:'eliminate', ids, kind, combo}
  {type:'moveOut', moves:[{id, col}]}
  {type:'undo', id}
  {type:'shuffle', changes:[{id, kind}], solvable}
  {type:'revive'}
  {type:'win'}
  {type:'lose'}
  ```

- **`core/bot.js`**：
  - `greedyMove(game) → id`
  - `playOut(game, {useProps}) → 'won' | 'lost'`
- **`art/icons.js`**：
  - `ICONS[16] = {key, name, color, svg}`，其中 `svg` 是 viewBox 为 64×64 的内部片段。
  - `iconSVG(kind) → '<svg …>'`
- **`art/dogs.js`**：
  - `BREEDS[6] = {key, name, team, colors}`
  - `dogHeadSVG(breed, mood) → '<svg …>'`
- **`audio/audio.js`**：`createAudio()` 返回一个对象，包含：
  - `unlock()`
  - `setMusic(bool)`、`setSfx(bool)`
  - `play(name, opts)`
  - `startMusic()`、`stopMusic()`
  - `setTension(0..1)`
- **`ui/*`**：由主线程集成，依赖上面所有模块。

### 9.3 构建

- `build.mjs` 按依赖顺序把每个模块包成一个闭包：

  ```js
  const __m_x = (() => { …; return { 导出名 }; })();
  ```

  并把 `import { a } from './x.js'` 改写成 `const { a } = __m_x;`。代码风格因此约定为：
  - 所有 import 写在文件顶部，并且只用具名导入。
  - 导出只用 `export function`、`export const`、`export class` 这三种形式。
- CSS 和 JS 内联进 `src/index.html`，同时输出两份：`dist/index.html` 是完整文档，自带 viewport-fit=cover 和安全区 padding；`dist/artifact.html` 是去掉外壳的片段，以 `<title>` 开头。构建完成后，校验两份产物里都没有外部资源引用：`src`/`href`/`url()`/`@import` 都不能指向 http(s)。
- 单元测试直接从 `src` 里 import ES 模块，所以测试时不需要先构建。

### 9.4 调试接口

- 在地址后加 `?debug`，会暴露 `window.__dog`：
  - `state()`
  - `solution()`
  - `step()`：按已知解走一步；洗牌之后改用机器人走。
  - `autoplay(ms)`
  - `win()`、`lose()`：直接跳到结算页。
  - `level(key, seed)`
- 加 `?seed=xxx` 可以固定自由练习的种子。
